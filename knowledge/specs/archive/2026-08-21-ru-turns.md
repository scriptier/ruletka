# Spec: automatic TURNS fallback (RU / DPI, no VPN)

**Status:** active · 2026-08-21  
**Locks:** CONNECTIVITY_LOCK · pool=0 · no always-on force_relay · no TCP 3478 dual-path storm

```text
GOAL: Users behind DPI (e.g. RU without VPN) get a TLS TURN path
      automatically. No Settings toggle. UDP 3478 stays first.
DONE WHEN:
  1) udpTurnOnly keeps turns: URLs; still drops turn:…transport=tcp
  2) pinTurnUrlToUdp never appends ?transport=udp onto turns:
  3) preferFastTurnFirst order: UDP 3478 → TURNS → TCP 3478
  4) Hub can list turns:… in ice_servers (same REST creds)
  5) Coturn tls-listening-port=5349 with valid certs; public 443 mux via sslh (ALPN → Caddy 8443, else TURNS)
  6) /config.json for RU/BY/IR/CN lists TURNS before UDP 3478 (≤400ms geo)
  7) TURNS certs refresh from Caddy without a manual copy
EVAL:
  - node ui/webrtc-udp-relay.test.mjs
  - cargo test ice_prefer_turns ice_order_tests connectivity_lock
  - After infra: ALLOCATE on 5349 from a TLS client
MUST NOT: pool>0; steal Caddy :443 on the same listener; invent product.ok
```

**Automatic for the user:** ICE tries every URL in `ice_servers`. Once TURNS is listed, they do nothing.

**5349 vs 443:** coturn stays on 5349. sslh owns public TCP 443 (`/etc/sslh.cfg`). Do not set `tls-listening-port=443` on coturn.
